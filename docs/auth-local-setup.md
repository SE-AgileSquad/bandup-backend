# Run the authentication API and Swagger locally

Run the commands below from the repository root. You need the .NET 10 SDK and Docker
Desktop with its Linux engine running. The frontend and Worker are optional for these auth
calls; the API still connects to PostgreSQL, Redis and RabbitMQ at startup.

## 1. Configure the dependency stack

Create the ignored environment file if it does not already exist:

```powershell
if (-not (Test-Path -LiteralPath infra/env/dev.env)) {
    Copy-Item -LiteralPath infra/env/dev.env.example -Destination infra/env/dev.env
}
```

Edit `infra/env/dev.env`. Use your chosen local passwords in place of `CHANGE_ME`. This
example uses alternative Redis and RabbitMQ ports:

```dotenv
POSTGRES_USER=bandup
POSTGRES_PASSWORD=CHANGE_ME
POSTGRES_DB=bandup
RABBITMQ_DEFAULT_USER=bandup
RABBITMQ_DEFAULT_PASS=CHANGE_ME
POSTGRES_PORT=5432
REDIS_PORT=16379
RABBITMQ_PORT=15673
RABBITMQ_MANAGEMENT_PORT=15672
```

Start Docker Desktop, then verify the engine and start the dependencies:

```powershell
docker info
docker compose --env-file infra/env/dev.env -f infra/docker/docker-compose.dev.yml up -d --wait
docker compose --env-file infra/env/dev.env -f infra/docker/docker-compose.dev.yml ps
```

Changing environment-file passwords does not replace credentials already initialized in
existing database or broker volumes. Keep the existing credentials or deliberately recreate
the disposable local stack. The existing README documents the data-removing `down -v` command.

## 2. Configure user secrets

The API and Worker already have `UserSecretsId` values; `dotnet user-secrets init` is not
needed. `set` overwrites individual values. If you intentionally want to reset the two
project stores, preserve any keys you still need before running:

```powershell
dotnet user-secrets clear --project src/BandUp.Api
dotnet user-secrets clear --project src/BandUp.Worker
```

Use the same usernames, database name, passwords and host ports as `dev.env`. The following
PowerShell prompts keep actual passwords out of this document:

```powershell
$bandupDbPassword = Read-Host 'PostgreSQL password from dev.env'
$bandupRabbitPassword = Read-Host 'RabbitMQ password from dev.env'
foreach ($bandupProject in @('src/BandUp.Api', 'src/BandUp.Worker')) {
    dotnet user-secrets set 'ConnectionStrings:Default' "Host=localhost;Port=5432;Database=bandup;Username=bandup;Password=$bandupDbPassword" --project $bandupProject
    dotnet user-secrets set 'Redis:ConnectionString' 'localhost:16379' --project $bandupProject
    dotnet user-secrets set 'RabbitMq:Host' 'localhost' --project $bandupProject
    dotnet user-secrets set 'RabbitMq:Port' '15673' --project $bandupProject
    dotnet user-secrets set 'RabbitMq:User' 'bandup' --project $bandupProject
    dotnet user-secrets set 'RabbitMq:Password' $bandupRabbitPassword --project $bandupProject
}
```

The API also needs a signing key. Generate it once for your local environment; replacing it
invalidates existing access JWTs:

```powershell
$bandupKeyBytes = New-Object byte[] 32
$bandupRng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
try {
    $bandupRng.GetBytes($bandupKeyBytes)
    dotnet user-secrets set 'Auth:SigningKey' ([Convert]::ToBase64String($bandupKeyBytes)) --project src/BandUp.Api
}
finally {
    $bandupRng.Dispose()
}
dotnet user-secrets set 'Captcha:Provider' 'Fake' --project src/BandUp.Api
dotnet user-secrets set 'Auth:RequireSecureCookies' 'false' --project src/BandUp.Api
dotnet user-secrets set 'Swagger:Enabled' 'true' --project src/BandUp.Api
```

The Worker does not need the signing key or CAPTCHA settings. The fake CAPTCHA provider
accepts exactly `fake-captcha-token`. It allows Swagger-only testing without frontend keys
or a challenge widget. Real Turnstile testing needs `Captcha:Provider=Turnstile`, the real
secret, and fresh challenge tokens generated by a client integration; Swagger has no widget.

## 3. Migrate and start the API

```powershell
dotnet run --project src/BandUp.Api --launch-profile http -- --migrate
dotnet run --project src/BandUp.Api --launch-profile http -- --urls http://localhost:18080
```

The second command overrides the launch profile's default port 8080. Port 18080 is an example,
not a guaranteed free port. For Windows socket error 10013, inspect both excluded ranges and
choose an available port:

```powershell
netsh interface ipv4 show excludedportrange protocol=tcp
netsh interface ipv6 show excludedportrange protocol=tcp
```

Keep using the same API host and scheme during a test. Cookies are scoped by host/path, not
by port. Open `/ready` on the selected origin, then `/swagger`:

- `http://localhost:18080/ready` should return `200` with no pending migrations.
- `http://localhost:18080/swagger` opens the API's own Swagger UI.

Local HTTP works because `Auth:RequireSecureCookies=false`. The production policy uses HTTPS
and secure cookies. `HttpOnly` prevents JavaScript from reading tokens; the browser still
stores and sends the cookies. Same-origin Swagger needs no manual JWT entry.

## 4. Exercise the auth flow in Swagger

Clear stale `bu_at` and `bu_rt` cookies for this host before a fresh walkthrough, especially
after changing the signing key. In Development, Swagger automatically adds the required
`X-Requested-With: bandup` header to same-origin JSON API mutations. The server's CSRF guard
remains enabled.

Register a unique email with `POST /api/auth/register`:

```json
{
  "email": "local-tester@example.com",
  "password": "ExamplePass123!",
  "displayName": "Local Tester",
  "captchaToken": "fake-captcha-token"
}
```

Registration returns `201` and creates the signup credit account. It does not sign in.
Call `POST /api/auth/login`:

```json
{
  "email": "local-tester@example.com",
  "password": "ExamplePass123!",
  "captchaToken": "fake-captcha-token"
}
```

Login returns `200` and sets the cookies. Then follow this sequence:

| Call | Request body | Expected result |
|---|---|---|
| `GET /api/auth/me` | None | `200` with the profile and current credit balance |
| `POST /api/auth/refresh` | `{}` | Empty `200`; both cookies are replaced |
| `GET /api/auth/me` | None | `200` using the renewed cookies |
| `POST /api/auth/logout` | `{}` | Empty `204`; both cookies are deleted |
| `GET /api/auth/me` | None | `401 UNAUTHORIZED` |
| `POST /api/auth/refresh` | `{}` | `401 INVALID_REFRESH_TOKEN` because the refresh cookie is missing |

Run these sequentially. Strict reuse detection intentionally rejects parallel refreshes and
revokes the user's remaining refresh sessions. If the access token expires before logout,
complete a refresh first, then logout using the updated browser cookies.

The login response currently has a placeholder credit balance; `/me` is the source of the
actual balance. See [implementation status](implementation-status.md) for deferred issues.

## 5. Use another HTTP client

Send both `Content-Type: application/json` and `X-Requested-With: bandup` on state-changing
requests carrying either session cookie. Refresh and logout require `{}` as their JSON body.
Tokens come from cookies, never body fields, query parameters or bearer headers.

For PowerShell, use a web session so it retains replacement/deletion cookies:

```powershell
$bandupApi = 'http://localhost:18080'
$bandupHeaders = @{ 'X-Requested-With' = 'bandup' }
$bandupLogin = @{
    email = 'local-tester@example.com'
    password = 'ExamplePass123!'
    captchaToken = 'fake-captcha-token'
} | ConvertTo-Json
Invoke-WebRequest "$bandupApi/api/auth/login" -Method Post -ContentType 'application/json' -Headers $bandupHeaders -Body $bandupLogin -SessionVariable bandupSession
Invoke-WebRequest "$bandupApi/api/auth/me" -WebSession $bandupSession
Invoke-WebRequest "$bandupApi/api/auth/refresh" -Method Post -ContentType 'application/json' -Headers $bandupHeaders -Body '{}' -WebSession $bandupSession
Invoke-WebRequest "$bandupApi/api/auth/logout" -Method Post -ContentType 'application/json' -Headers $bandupHeaders -Body '{}' -WebSession $bandupSession
```

For browser integration and concurrency rules, see [the client contract](auth-client-contract.md).
For automated acceptance coverage, see [the acceptance matrix](auth-session-acceptance.md).
